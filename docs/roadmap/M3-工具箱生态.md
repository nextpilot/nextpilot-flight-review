## 2. 关键拍板（v1 定稿；异议先改本文档再动代码）

1. **载体口径**：扩展包（Pack，纯数据清单）与插件（C ABI 动态库）**分离**。
   工具箱 zip = 数据包（必然有）+ 可选随包插件文件。数据包不携带代码——
   包内解析器条目只**引用已注册解析器 id**（如 `mdf4`），mount 时校验存在，缺失即拒装并报缺什么。
2. **zip 读端自写**（延续 XlsxBook 零依赖先例）：新机制库 `src/libs/archive`，支持
   store + deflate 两法。deflate 解压照 zlib `puff.c` 逻辑自写 inflate（约 300 行，
   成熟参考实现，非发明算法）。**不引第三方库**。外部 zip 默认 deflate，读端必须支持。
3. **首批包"分析面板"形态**：纯数据包不做新 QWidget——分析能力用
   **画布布局预设 + UiAction 预置 PlotSpec JSON（data 字段）+ 检查清单 ReportTemplate** 承载。
   需要真代码的分析后置到 Plugin 线。
4. **Plugin dlopen 小步**：M3 只放开"解析器插件"一种类型（SPI 已有）；
   面板/意图的 C ABI 贡献后置 M4+。
5. **借鉴 PlotJuggler 4（2026-09 的 4.0）生态模型**（对标详见 §10）：
   - registry 用 **git 仓库 + JSON 目录**起步（pj-plugin-registry 形态，零服务端成本）——记入 M4+ 演进路线（§6.1）；
   - **hello-world 必须配可获取的模板包源**（pj-official-plugins 的"官方插件仓库即作者模板"做法）——M3.4 验收物升级为可 clone/复制的模板包目录；
   - **守住我们更强的安全面**：PJ4 四类贡献全是 C++ .so（同进程直摸数据 API），我们数据包纯数据、行为只留解析器一条 C ABI 缝——不追 PJ4 的灵活性而扩大动态库攻击面。

## 3. 打包格式规范（toolbox.zip）

```
<toolbox-id>/                        # zip 根目录（单顶层目录）
├── manifest.json                    # 必填，唯一
├── packs/*.json                     # Pack 清单 JSON（≥1 个）
├── plugins/                         # 可选：随包插件（安装时拷入插件目录）
│   └── psplug_xxx.so
├── docs/*.md                        # DocEntry location 指向
├── samples/...                      # DataAsset 示例数据
└── presets/...                      # 布局预设/参数 preset（UiAction.data 引用）
```

### manifest.json schema（全部必填字段缺失即拒装）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一，kebab：`toolbox.px4-tuning`；与已装包 id 冲突即拒（升级=先卸后装） |
| `name` | string | 显示名，如「PX4 调参工具箱」 |
| `version` | string | 语义版本 `x.y.z` |
| `domain` | string | 枚举值 = `Domain`（autopilot/automotive/gnss/robotics/general） |
| `author` | string | 作者/组织 |
| `compat` | string | 兼容声明 `>=x.y`（一期仅解析与随包展示，不硬拒；留 M4 硬校验） |
| `description` | string | 一句话说明（可空） |

### packs/*.json → Pack 结构映射

| JSON 字段 | Pack 字段 | 说明 |
|---|---|---|
| `id` / `name` / `domain` | 同名 | 包 id 全局唯一；`packs.<packid>` 惯例 |
| `uiActions[]` | UiAction | 字段一一对应（id/label/area/intentOp/data/icon/galleryGroup/visual/shortcut/order/large/checkable） |
| `panels[]` | PanelSpec | id/label/area/icon/data |
| `scripts[]` | ScriptSpec | language/source/exports/id/label |
| `dataAssets[]` | DataAsset | id/label/location/format/description；**location 必须相对包根且解压后存在**，安装器校验 |
| `docs[]` | DocEntry | id/title/location/mime；同上校验存在 |
| `examples[]` | ExampleEntry | id/title/location/description |
| `reports[]` | ReportTemplate | id/title/description/sections[]（kind ∈ title/metadata/canvas/text） |
| `parsers[]` | （引用） | **字符串数组 = 已注册解析器 id**（ParserHub::entry 校验），非实现载体 |

**校验规则**（安装器执行，顺序即优先级）：
1. manifest 必填字段齐 + domain 合法；
2. 每个 pack JSON 解析成功 + 包内 `packs/*.json` ≥1；
3. 包 id / 全部条目 id 与**已挂载包**无冲突（ToolboxHub::mount 二次防线也在）；
4. `parsers[]` 引用的解析器 id 全部已注册（缺失→报错列出缺什么）；
5. dataAssets/docs/examples 的 location 文件在解压目录真实存在；
6. zip 内禁止 `../` 路径穿越与绝对路径条目（reader 层拒绝）。

## 4. 安装器设计（host 系统级命令，对齐 data.* 风格）

### 意图面（新 `src/application/host/include/ToolboxCommandsHandler.h/.cpp`，系统级、不归属可卸载模块）

| op | 入参 | 行为 |
|---|---|---|
| `toolbox.install` | `path`（zip 绝对路径） | 校验→落盘→mount→返回 `{installed, packIds, warnings}` |
| `toolbox.uninstall` | `id` | unmount(packId)→删目录；返回 `{uninstalled}` |
| `toolbox.list` | — | 已装包清单（id/name/version/domain/条目计数） |
| `toolbox.info` | `id` | 单包详情：七类贡献逐条列出 |

- 安装落盘：`QStandardPaths::writableLocation(AppDataLocation) + "/toolboxes/<id>-<version>/"`。
- **启动重挂**：host 装配期扫 toolboxes 目录，逐包读 manifest/pack JSON → mount
  （等价内置包的运行期版；单包损坏只记 warning 不阻断启动——插件互不牵连同款隔离）。
- **卸载顺序红线**：先 `unmount` 成功再删目录；unmount 失败不动磁盘。
- 升级 = `toolbox.uninstall` + `toolbox.install`（一期不做原地升级）。

### GUI 接线（M3.1c）

- MainWindow 拖入 zip（dropEvent 接 `.zip`）→ 发 `toolbox.install`；成功 toast + 诊断树可见新 extension 节点。
- ribbon 数据组加「工具箱」入口（UiAction 由 host 骨架槽声明）→ 已装包管理页：列表 + 卸载 + 安装按钮。
- CLI/脚本同一条意图路径可用（headless 验收主通道）。

## 5. zip 读端设计（新机制库 `src/libs/archive`）

- target：`ps_archive`（STATIC，仅链 Qt Core），PUBLIC include `include/ZipReader.h`。
- API（最小面）：

```cpp
namespace nextpilot::plotscope::archive {
struct ZipEntry { QString name; quint64 size; quint32 crc32; };
class ZipReader {
public:
    explicit ZipReader(const QString &path);   // open 失败 ok()=false，errorString() 给原因
    bool ok() const;
    QString errorString() const;
    QList<ZipEntry> entries() const;           // 目录条目跳过
    QByteArray read(const QString &name);      // 失败返回空 + errorString 置因
};
} // namespace
```

- 实现要点：本地头/中央目录/EOCD 三段解析（与 XlsxBook 写端对称）；
  method 0（store）直读、method 8（deflate）走自写 inflate（puff.c 逻辑）；
  CRC32 校验失败报错；**拒绝**绝对路径、`..` 穿越、加密条目（flag bit 0）、
  跨盘/分卷（disk number ≠ 0）；顶层目录唯一性校验放安装器（schema 层）。
- 单测 `tests/test_zip_reader.cpp`：
  store 包 / deflate 包（用本仓库 XlsxBook 生成 store 包 + 手工构造 deflate 条目）/ CRC 损坏 /
  路径穿越拒收 / 加密位拒收 / 空 zip / 截断文件。

## 10. 与 PlotJuggler 4 插件机制对标（2026-11-22）

| 维度 | PJ4 | 我们 M3 | 结论 |
|---|---|---|---|
| 插件分类 | 四类：loader/streamer/parser/toolbox | 七类贡献 + 解析器（行为式） | 同构，我们的分类更细 |
| 元数据清单 | content_manifest + PluginCheckRunner 安装期校验 | manifest.json + 六条校验规则（§3） | 直接对齐 |
| 归档解压 | ArchiveExtractor | ZipReader（自写 store+deflate，§5） | 同构 |
| 行为载体 | **四类全是 C++ .so**（同进程直摸数据 API） | 纯数据包 + 仅解析器走 C ABI | 我们隔离面更小，守住（§2.5） |
| 参数面板 | filter 自描述 schema → 宿主生成 ParameterForm（无手写 Qt） | UiAction/ParamSpec 声明式 UI（ps_uischema） | 同一条路线，互相印证 |
| 脚本引擎选择 | 文件头 directive（`-- pj-script: luau`） | ScriptSpec.language 字段 | 等价 |
| 分发演进 | PJ3 手动装 → PJ4 registry + 应用内市场 + 更新 | M3 本地 zip → M4 registry/市场/更新（§6.1） | PJ4 演进史即我们 roadmap 的预演 |
| 卸载/隔离 | .so 卸载风险大（Windows 替换 DLL 需先关进程） | unmount 原子撤销 + 失败隔离（数据包无代码） | 我们更强，保持 |

**总评**：机制同构、路线一致，M3 设计不需因 PJ4 改动；采纳两点（registry git 仓库形态、模板包仓库做法），守住一点（动态库安全面）。

## 7. 与既有机制的衔接点（执行 agent 对照）

- `ToolboxHub::mount` 已做包 id/条目 id 唯一性校验与 provider 自动写入——安装器是第一道，mount 是第二道，两道都留。
- 解析器引用校验走 `ParserHub::entry(id)`（静态表，遗留 4 收口后 ParserNode 上树可诊断）。
- 诊断：装包成功后 `diag.registries` 的 `extension` 节点 count/keys 变化——M3.1c 用它做测试断言。
- 用户目录惯例对齐 `SettingsStore`：`QStandardPaths::AppConfigLocation`（配置）/ `AppDataLocation`（toolboxes 落盘）。
- XlsxBook zip 写端在 host 层且偏 OOXML 专用——**不要复用它做读端**；读端是新机制库 libs/archive，将来若需写端再议合并。
