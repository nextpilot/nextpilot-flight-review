# M2.7 · Rust kernel 优化与功能补全

> 状态：规划中（2026-11 评审产出）。基于对 ps-ndf/ps-abi/ps-ops 全量代码审查
> （typed.rs 911 行 / abi 1913 行 / ops ~1600 行）+ 多表 dataset 模型确认。
> 前置结论：数据面保持列存（不用 SQLite，见 ADR 讨论），M2.5 编辑 ABI 不预投资。

## 背景事实（代码依据）

- C++/Python 取数只有两条路：`ps_dataset_value_at`（逐元素 FFI）与
  `ps_dataset_read_window`（降采样+强转 f64，画布专用）——**无整列原始读取**。
- `lod_minmax`（typed.rs:542）每次调用线性扫全区间，**无金字塔缓存、无增量续算**。
- 全部 ops（stats/fft/iir/decimate）顺序执行，无 rayon/显式 SIMD。
- `lower_bound/upper_bound` 假设时间轴严格有序，append 无校验。
- ULog 多表模型：每 topic 一张 typed 大表（百万行级）+ 参数/事实/事件小表（千行级）。

## 优化点（按收益排序）

| # | 条目 | 现状问题 | 方案 | 预期收益 |
|---|---|---|---|---|
| 2.7.1 | **整列原始读取 ABI** ⭐ | value_at 逐元素 FFI；M2.2 列统计、M2.6 Python push 全在循环里，100 万行 26ms 大部分是调用开销 | `ps_dataset_column_raw(ds, table, column, out_ptr, out_len, out_type)` 返回内部缓冲 const 指针+长度+类型码，C++/shm 按类型直读 | Python push 26ms → **≤2ms**；列统计/导出同量级提升 |
| 2.7.2 | **LOD 金字塔 + 增量续算** ⭐ | 每次渲染全量重扫（全景 100 万行，拖拽每帧 100 万行）；append 后无增量 | 每列分层 minmax（level0=原始，level_n=每 4 行聚合），append 纯前缀增量续算；视口读 O(px) | 渲染复杂度与缩放级别/行数解耦；live 同受益 |
| 2.7.3 | 批量统计并行化 | 单线程顺序执行 | rayon 按列 par_iter（stats/decimate 批量入口） | 多列/批量场景近线性加速 |
| 2.7.4 | read_window 类型特化快路径 | 每行 value_as_f64 分发+null 检查 | 按列类型特化循环（有金字塔后此路低频，优先级降） | 放大视图读更省 |

## 功能缺口

| # | 条目 | 验收条目 |
|---|---|---|
| 2.7.5 | **数据集切片**：按时间范围/列子集抽出新 PsDataset | 选段导出、"只导出该 topic"、M2.6 写回 v2 物化一趟 ABI 完成；单测：切片内容与原集逐点一致 |
| 2.7.6 | **多列对齐读取**：一次读同表多列对齐行区间 | 画布多通道叠加/Python 导出 DataFrame 不再逐列分别读；单测：多列行对齐 |
| 2.7.7 | **乱序校验**：append 校验时间轴单调（或显式声明容忍策略） | 乱序注入要么报错要么文档化行为，杜绝二分静默出错 |

| 2.7.9 | 分位数统计（P50/P95/P99） | stats_series 增分位数出口；飞行分析常用（延迟/掉速 P99） |

## 明确不做

- 编辑 ABI（in-place/COW）——M2.5 搁置，delta-overlay 不动 kernel
- SQL/查询引擎——多表无 join 需求（元数据小表千行级，线性扫足够）
- mmap 后备存储——会话寿命内存常驻是对的，ps-cache 已覆盖持久化

## 落地顺序

1. **第一批：2.7.1 + 2.7.5**（都在 ps-abi 加函数；C++ Dataset 门面加两个方法；
   M2.2/M2.6 消费端小改）→ 直接兑现"Python 往返 ≤2ms + 选段导出"，
   附 ng_test_kernel 基准对比（前后耗时写进提交信息）。
2. **第二批：2.7.2**（纯 Rust 内部改造，ABI 不变；渲染基准：全景拖拽帧耗时前后对比）。
3. **第三批：2.7.6/2.7.7/2.7.9**（小项打包）；2.7.3/2.7.8 视 live 场景成熟度再排。
