### 实现要点（踩坑记录）

- **每文件独立 VM**：`batch = {file, dataset}` 前置 chunk 注入上下文，脚本 `return {...}` 经
  `runStringResult` 转 QVariantMap 进汇总行——指标约定零新机制。
- **空解析判定**：摄取管道对垃圾文件宽容（0 表数据集也算成功），批量语义里"0 表"即损坏
  → load 阶段失败，明细可追。
- **两套 id 空间**：`data.remove` 收**源 id**，数据集 id 须 `SourceRegistry::sourceOfDataset`
  反查后才能删（单测抓出：dataset#2 常驻不删 → count 断言失败）。
- **data.remove 回收是同步的**，但测试里源移除到数据集移除隔一个事件循环——断言前先
  processEvents 冲一遍。
- **Qt6 无 QRegExp**：pattern 切分用 `QRegularExpression`。
- 顺手修复：`ScriptModule::initialize` 里 `viewDispatcher` 被 `std::move` 后复用（REPL 的
  view 回退拿到空派发器）→ 改为传拷贝。

## 技术要点

- **顺序执行 + 事件循环分片**：每文件处理完回到事件循环（进度 UI 可刷新、取消请求可插入），
  不做线程池并行（一期文件间无依赖但共享 VM 状态，并行复杂度不值）。
- **失败明细**：`{file, stage, error}` 数组进意图结果 payload；GUI 汇总表 + headless JSON 双出口。
- **汇总表**：脚本每文件产出关键指标（print 约定或 return 表）→ 汇总 CSV/表格面板。
- **与 M2.3 衔接**：批量结果可一键逐文件出报告（report.export 的 headless 路径复用）。
