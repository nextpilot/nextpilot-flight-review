# M2.4 · 批量处理

> 状态：待做（M2.3 之后）。脚本工作台（M2.1）的自然延伸——脚本 + 目录遍历 + 汇总。

## 目标

100 个 ULog 一键跑完出汇总：每个文件跑同一组脚本/派生，失败明细准确，可取消。

## 条目

| # | 执行条目 | 验收条目 |
|---|---|---|
| 2.4.1 | `data.batch.run {dir, script}` 意图 + 失败明细汇总 | 单测：3 个文件 1 个损坏 → 2 成功 1 失败明细准确 |
| 2.4.2 | 进度反馈（取消支持）+ 批量报告汇总表 | 100 文件级可取消；汇总表含每文件关键指标 |

## 技术要点

- **顺序执行 + 事件循环分片**：每文件处理完回到事件循环（进度 UI 可刷新、取消请求可插入），
  不做线程池并行（一期文件间无依赖但共享 VM 状态，并行复杂度不值）。
- **失败明细**：`{file, stage, error}` 数组进意图结果 payload；GUI 汇总表 + headless JSON 双出口。
- **汇总表**：脚本每文件产出关键指标（print 约定或 return 表）→ 汇总 CSV/表格面板。
- **与 M2.3 衔接**：批量结果可一键逐文件出报告（report.export 的 headless 路径复用）。

## 杀手场景（验收演示）

选目录（含 1 个故意损坏文件）→ 批量运行 → 进度条走完 → 汇总表 99 行指标 + 1 行失败明细
（文件名/阶段/原因）→ 中途点取消能停。
