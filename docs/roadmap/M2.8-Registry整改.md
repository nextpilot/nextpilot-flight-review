# M2.8 · Registry 机制整改（RegistryNode / 注册树）

> **状态：v3 设计定稿，文档锁定。** 本版吸收 RT-Thread `rt_object` 节点范式
> （用户拍板），并经架构师必要性裁决修剪（revision/batch/部分迁移推迟）。
> 执行 agent 不需要重构决策权——有歧义按本文档裁决；文档没写的按
> "最小改动 + 测试常绿"处理。**锁文档后不再接受增量拍板（含架构师自己）。**

## 1. 背景与诊断

现状：九张注册表三种写法（Dataset/Source/DerivedSeries/Interaction/UiSlot/
Extension/PanelFactory/BuiltinModule/Registry<T> 模板），API 方言不一
（insert vs add、keys vs ids）、信号各自发明、无全局可观测性——无法回答
"系统现在有哪些注册表、各有多少条、谁刚变化了"。

**范式定稿（用户拍板）**：借鉴 rt_object——注册不是某个管理器的功能，是
**对象自带的属性**。创造 `RegistryNode`：继承即自动获得注册/卸载能力，
全体注册对象挂**一棵树**，`(type, name)` 即可查找定位。子类不再需要叫什么
"Registry"——它只是一个具备自动注册能力的对象。

**一条硬约束（架构师纠正，照搬 rt_object 会翻车）**：rt_object 的对象是静态
存储的活结构体（地址终身稳定），所以能内嵌链表节点。我们的条目大多是**值类型**
（DataSourceInfo/UiSlot/贡献 struct，按值存于 QHash/QList，扩容即搬家），
做成节点会让链表指针悬空。因此**分两层**：

```
RegistryTree（一棵树，组合根持有）
└── 按 kind 分叉
      └── RegistryNode 节点（活对象：注册表/模块——构造自动上树，析构自动摘除）
            └── 条目 = 节点内的值数据（不上树、不做成节点）
                 经节点暴露 count/keysAsStrings —— 从树上看完全可枚举
```

对外效果与愿景一致：继承即注册、一棵树、(kind,name) 查找；差别仅在树上的
节点是活对象层，值条目经节点间接可枚举。

## 2. 目标设计

### 2.1 RegistryKind（libs/registry/include/RegistryNode.h）

```cpp
// 注册表类型标签【拍板：枚举且非虚】——kind 集合是核心封闭集（M3 扩展包
// 贡献条目，不发明新表）。kind 是身份不是行为，构造时定死，子类零样板。
enum class RegistryKind : quint8
{
    Dataset, Source, DerivedSeries, Interaction,
    UiSlot, Extension, PanelFactory, BuiltinModule
};
QString kindName(RegistryKind);   // QMetaEnum 转字符串（diag JSON 用）
```

### 2.2 RegistryNode（同头文件）

```cpp
// 注册节点基类【范式拍板】：继承即自动获得注册/卸载能力，全体节点挂一棵树。
// (kind, name) 即 rt_object 的 (type, name) 二元组——name 给人看，kind 给机判。
class RegistryNode : public QObject
{
    Q_OBJECT
public:
    // 身份构造时定死；tree 由组合根传入（禁止全局单例）。
    RegistryNode(RegistryTree &tree, RegistryKind kind, const QString &name,
                     QObject *parent = nullptr);
    ~RegistryNode() override;        // 析构自动从树摘除

    // ---- 身份（非虚）----
    RegistryKind kind() const;
    QString name() const;

    // ---- 可观测（子类实现；条目经节点间接可枚举）----
    virtual int count() const = 0;
    virtual QStringList keysAsStrings() const = 0;

Q_SIGNALS:
    // 统一信号【拍板：带 key】——消费方可精准响应"某条"（画布联动铺路）。
    void objectAdded(QVariant key);
    void objectRemoved(QVariant key);
};
```

### 2.3 RegistryTree（libs/registry/include/RegistryTree.h）

```cpp
// 全系统注册树（等价 rt_object kernel object container）。
// 组合根（AppContext）创建持有——不做静态单例，测试间树完全隔离。
class RegistryTree
{
public:
    void attach(RegistryNode *node);   // 节点构造时自动调
    void detach(RegistryNode *node);   // 节点析构时自动调
    QList<RegistryNode *> nodes() const;          // 全树枚举
    RegistryNode *find(RegistryKind kind) const;  // 按 kind 找节点
};
```

### 2.4 TypedRegistry<T, Key>（libs/registry/include/TypedRegistry.h）

```cpp
// 通用注册节点：RegistryNode 机制 + 泛型存储，一次实现全类型复用
// 【拍板：一 template + 一 type 区分】。owner 语义在这里（不在基类——
// 只有 Extension/UiSlot 等少数表有提供者概念，不强迫全部节点实现）。
template <typename T, typename Key = QString>
class TypedRegistry : public RegistryNode
{
public:
    Key add(T entry);                              // Key=int 时自动分配 id
    Result<Key> addWithStableId(T entry, Key id);  // 录制/回放稳定 id
    bool remove(Key id);
    T *get(Key id);
    QVector<Key> ids() const;
    int count() const override;
    QStringList keysAsStrings() const override;
    bool removeByOwner(const QString &owner);      // 按提供者原子撤销
    void clear();
Q_SIGNALS:
    void entryAdded(Key id);   // 类型安全别名（转发基类 objectAdded）
    void entryRemoved(Key id);
private:
    Registry<T, Key> m_table;        // 存储继续委托现有模板（红线：不改它）
    QHash<Key, QString> m_owners;
    Key m_nextId = 0;
};
```

#### 2.4.1 `Registry<T,Key>` 保留裁定（三层选型，执行 agent 不再讨论）

`Registry<T,Key>` **保留且不删**——它是存储原语，不是整改对象：

1. `TypedRegistry` 是**组合**它（`m_table`），不是替换它；删掉等于重写存储层（保序语义、
   `find()` 可变指针等已验证行为全部重测），零收益纯风险。
2. 一批直接使用者付不起 TypedRegistry 的重量：工具箱 7 张声明式表（纯数据，全变树节点
   只会给 `diag.registries` 添噪音）；OpDispatch 意图分发表（函数指针，无生命周期）；
   StaticRegistry/AutoRegistrar 静态通道（**QObject 无法在静态初始化期安全构造**，
   物理上必须建在无 QObject 的轻容器上）。

整改后的三层选型（纪律线）：

| 层 | 类 | 用途 | 谁允许直接用 |
|---|---|---|---|
| 活对象 | `RegistryNode` / `RegistryTree` | 继承即注册，挂树，(kind,name) 发现 | 模块/扩展/面板宿主等有生命周期的对象 |
| 登记表 | `TypedRegistry<T,Key>` | 需要信号/owner/id 分配的值登记表 | Dataset/Source/DerivedSeries 等运行态表（壳迁入） |
| 存储原语 | `Registry<T,Key>` | 保序容器底座 | 仅限 registry 库内部、纯数据声明式表（工具箱 7 张表）、静态自注册通道 |

纪律更新：**业务登记表禁止裸用 `Registry<T>`**——有生命周期走 TypedRegistry，是活对象
就继承 RegistryNode；`Registry<T>` 只服务上述三类。同步更新 ARCHITECTURE.md 选型表。

### 2.5 诊断出口：`diag.registries` 意图

host 注册 view action，树的全景 dump（每节点一项）：

```
[ {kind:"dataset", name:"数据集", count:2, keys:["1","2"]},
  {kind:"extension", name:"扩展包", count:1, keys:["ng_test_report_template"]},
  ... ]
```

这是整改的核心验收物——整改前不存在任何途径可以获得这张清单。

### 2.6 设计拍板（定稿四条，执行 agent 不再讨论）

1. **节点模型**：继承 `RegistryNode` 即自动注册/卸载，全系统一棵树，
   `(kind, name)` 定位；**值条目不上树**（地址不稳定），经节点间接可枚举。
2. **kind 枚举非虚 + name 构造传入**；**只统一元层**——领域 API
   （get/add/remove/update）不改名，禁止为统一而批量改调用点。
3. **信号带 key**：`objectAdded(QVariant)/objectRemoved(QVariant)`；各子类旧
   具名信号（datasetAdded 等）保留，与基类信号并存（测试零改动）。
4. **树归组合根**：AppContext 创建持有，不做静态单例；static 注册表由 host
   装配时显式构造上树（QPointer 弱引用语义，析构自动摘除）。

1. **回归基线**：每阶段结束 Release/Debug ctest 全绿（当前 30/30）；只增不减。

4. **静态纪律**：树不托管 static 节点生命周期；有生命周期的实例归组合根。
