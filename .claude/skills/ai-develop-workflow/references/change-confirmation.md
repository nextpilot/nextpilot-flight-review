# 变更前确认

## 适用范围

本规范约束一切**修改类操作**：代码、文档、skill、配置、构建脚本、任务文档等。只读操作（读文件、盘现状、跑测试、查资料）不受约束。

## 核心规则

1. **复述先行**：收到修改类指令后，第一响应是复述理解，不是动手。复述必须包含：
   - 要改什么：对象与范围；
   - 打算怎么改：方案要点、落点文件；
   - 理解中含糊或有多种解释的地方：显式列出，向用户确认，不得自行择一理解后闷头执行。
2. **同意后才动手**：用户对复述作出明确肯定表态（同意/对/开工/拍板）后方可修改。沉默、未回复、话题转移、仅提问均不构成同意。
3. **复述有误即纠正**：用户指出理解偏差时，重新复述修正后的理解，再次等待确认；不得以“差不多”为由直接按原理解执行。
4. **方案未讨论清楚不动手**：复述和确认过程中暴露出的歧义、未裁定分叉，先讨论或补齐事实，再进入执行。

## 执行流程

1. 收到修改类指令。
2. 输出复述：对象与范围 + 方案要点 + 含糊点提问。
3. 停止，等待用户表态。
4. 用户明确同意 → 执行；用户纠正 → 回到步骤 2；用户提出新问题 → 先回答，再回到步骤 2。
5. 执行过程中若发现与复述内容不符的新情况（牵连面扩大、方案不可行），停下再次复述并等待确认，不得顺势扩大改动。

## 自查

每次动手修改前自问：这次修改的对象、范围、方案是否已经用户明确确认？任一项没有，则回到复述步骤。
