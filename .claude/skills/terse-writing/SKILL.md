# 简短写作

写注释、文档、提交信息、回复时，目标是让读者一眼看懂当下这段代码/这件事，**不是**留下思考过程。

## 两条禁令

**1. 不引用出处。**
不写「见 master-plan §7」「根据 AGENTS.md §5」「遵循 XX 铁律」。
理由：文档会改版，问题会修复，引用会指向过期内容；后来的人为了一句无效引用，得同步一整片文字。
做法：要说什么就直接说，让文字自足，不依赖任何外部文件。

**2. 不追述历史。**
不写「历史上踩过这个坑」「当初否决了另一方案」「实测发现」「这是第 N 次修正」。
理由：这些是写作者当时的过程，不是读代码的人需要的当下信息；时间一过全是无噪音。
例外：确实有一段背景不写就无法理解当前代码（比如某写法是在绕一个真实存在的坑），才写，且压到一两句。

## 注释写什么

三件事，一两行为主：

- **做什么**——这段代码的目的（名字已说清就不写）。
- **怎么做**——只写不易从代码看出的意图或约束。
- **简单原因**——只在原因不明显时写一句。

## 反例与正例

反例（堆历史、引用、Markdown 修饰）：
```
// 这是所有具体注册表的公共最小实现（见 master-plan §7）。
// 历史上各写一份 QHash，踩过不一致的坑，2026 年重构时改为委托本模板。
// 各具体表退化为「定义类型 + 薄壳委托」，不再各写一份。
```

正例：
```
// 泛型注册表：id → 条目的增删查遍历。具体表定义条目类型后委托本模板。
```

## 自查

写完一段，问：相关文档下次改版，这段会不会变错或变无关？会，就删掉，或改成不依赖文档的自足表述。
