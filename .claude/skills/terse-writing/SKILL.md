# 简短写作规范

## 一、目的与适用范围

注释、文档、提交信息及回复的目标是使读者能直接理解当前代码或事项，而非留存写作者的思考过程。本规范约束上述各类说明性文字的内容取舍与篇幅。

## 二、两条禁令

### 禁令 1：禁止引用出处

不得书写「见 master-plan §7」「根据 AGENTS.md §5」「遵循 XX 铁律」一类引用。

- 原因：文档会改版，问题会修复，引用终将指向过期内容；后继者需为一条无效引用同步整段文字。
- 做法：应表述的内容直接写明，使文字自足，不依赖任何外部文件。

### 禁令 2：禁止追述历史

不得书写「历史上踩过这个坑」「当初否决了另一方案」「实测发现」「这是第 N 次修正」一类过程性表述。

- 原因：此类内容是写作者当时的过程记录，非读者所需的当下信息，时效过后即为噪声。
- 例外：确有背景不写则无法理解当前代码（如某写法是在规避一个真实存在的问题）时，可写，但应压缩至一至两句。

## 三、注释的内容构成

注释只承载以下三项，以一至两行为主：

| 内容 | 说明 |
|---|---|
| 做什么 | 该段代码的目的；名称已表达清楚时不写 |
| 怎么做 | 仅写不易从代码直接看出的意图或约束 |
| 简单原因 | 仅在原因不明显时写一句 |

## 四、示例

不合格（堆砌历史、引用与过程叙述）：

```
// 这是所有具体注册表的公共最小实现（见 master-plan §7）。
// 历史上各写一份 QHash，踩过不一致的坑，2026 年重构时改为委托本模板。
// 各具体表退化为「定义类型 + 薄壳委托」，不再各写一份。
```

合格（自足、直白、无冗余）：

```
// 泛型注册表：id → 条目的增删查遍历。具体表定义条目类型后委托本模板。
```

## 五、自查

完成一段说明性文字后，应自问：相关文档下次改版时，这段文字是否会变错或变得无关。若是，则删除，或改写为不依赖文档的自足表述。
